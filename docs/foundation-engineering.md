# SonTool v3.0 · 첫 Foundation Engineering 지시서

대상: 다음 Codex Astra Ultra 기초공사 세션. 모델 선택과 별개로 아래 근거와 검증 기준을 적용한다.

## 목표와 시작 상태

사람과 여러 AI가 같은 작품을 필요한 부분만 수정하고, 여러 표현 매체로 발전시킬 수 있는 공통 창작 기반을 검증·구현한다. 코드량보다 이식성·수정 보존·복원·실제 재생의 증거를 우선한다.

이 저장소에는 초기 구조 검증기와 합성 예제만 있다. **아래 작업은 아직 수행되지 않았다.** 먼저 `AGENTS.md`, `architecture.md`, `sjg-format.md`, `integrations.md`, `decisions/0001-bootstrap.md`를 읽고 `npm ci --ignore-scripts`와 `npm run check`로 출발 상태를 확인한다.

확정 방향은 공통 `.sjg` 작품, SonTool GPT와 App, 작품→페이지→장면→블록, 내용·배치·시간·행동·상태, 사람·AI 공동 편집, Skill·Template 연결, 비공개 미리보기 후 승인 발행, 독립 확장 모듈이다. JSON 초안·세부 필드·프레임워크는 영구 결정이 아니다.

과거에 별도로 언급된 설계안 첨부 전체는 이 저장소에 포함되어 있지 않다. 읽었다고 주장하거나 내용을 만들어 넣지 않는다. 현행 사용자 지시와 소유 시스템의 정본을 먼저 읽고, 실제로 필요한 누락만 명시한다.

## 1. 조사: 만들기 전에 연결할 수 있는 것을 찾는다

다음은 조사 대상이며, 이름만으로 존재·동작·공개 가능성을 확정하지 않는다.

- 손잡고의 손툴·씬플레이 Project 9와 Task 121의 현행 지시·Work·최신 작업보고. 새 v3.0 범위와 기존 작업의 차이를 보존한다.
- SonEditor·SonTool·SonMode·ScenePlay와 `@sone/tool`의 core/React/document/transitions 자산. 정확한 위치·별칭·소유 저장소·라이선스를 확인한다.
- 손잡고 MCP의 `sontool_create`, `sontool_update`, `sontool_publish`: 인증, 비공개 저장·미리보기, 발행 승인, 입력·응답·오류 계약.
- SonE의 Meaning·Skill·Template 참조 및 리비전·접근권한 계약.
- ChatGPT Sites·MCP Apps 및 실제 파일·편집 UI의 현재 지원 범위. 문서 지원과 대상 계정에서의 실측을 구분한다.
- 공개 편집기 Puck·GrapesJS 등에서 재사용할 수 있는 부분과 직접 만드는 작은 계층의 비용.
- Remotion·FilmCraft의 실제 연결점, 파일 계약, 라이선스와 읽기·쓰기 지원.

조사표에는 대상·정확한 출처/버전·접근 가능 범위·확인한 기능·미확인·재사용 판단을 적는다. 상태는 **존재 확인 / 구현 확인 / 대상 환경에서 실측 / 설계만 확인 / 권한 또는 자료로 확인 불가**로 나눈다. 검색 0건은 부재 증거가 아니다. 로컬 보고를 운영 검증으로 승격하지 않는다.

**공개 이식 권한은 별도다.** 비공개 코드를 읽을 수 있어도 이 저장소로 복제할 수는 없다. 공개 코드만 라이선스와 출처를 확인해 재사용하고, 나머지는 계약 경계 또는 어댑터로 연결한다. 개인 데이터·인증 정보는 보고와 예제에서도 제외한다.

## 2. 결정: 근거와 작은 실험으로 고른다

1. **공통 모델:** 랜딩·스크롤·선택형 작품이 같은 구조에서 성립하는지 실제 재생까지 확인한다. 원문과 표현을 분리하고, 내용 수정과 배치·시간 수정의 경계를 검증한다.
2. **파일 형식:** JSON, ZIP+manifest, Markdown/구조화 본문을 비교한다. 자산 포함·외부 참조·상대경로·파일 크기·호환성·손상·마이그레이션을 포함해 `.sjg` 내부 형식을 결정한다. 현재 확장자만으로 컨테이너를 확정하지 않는다.
3. **모듈:** ID/버전·데이터 스키마·편집 및 재생 진입점·의존성·권한·AI 수정 범위·미지원 대체 표현을 정의한다. 두 번째 모듈 추가 때문에 core를 수정해야 한다면 경계를 재검토한다.
4. **공동 편집:** 안정 ID와 정확한 대상 조회, base revision, 원자적 변경 묶음, 충돌 거절, 되돌리기 및 이력을 정한다. CRDT나 새 DB가 필요하다고 미리 가정하지 않는다.
5. **호스트와 어댑터:** core와 GPT/App UI, AI 제공자, 웹/영상 재생기, 서비스 저장·발행을 분리한다. 서로 다른 매체의 손실을 명시한다.

선택한 안·대안·판단 근거·비용·미확정·호환성 영향을 짧은 decision record로 남긴다. 초안 모델이 검증을 통과하지 못하면 버전을 바꾸며 수정하고 기존 작품을 조용히 덮어쓰지 않는다.

## 3. 최소 구현 구간

허용된 격리 브랜치에서 다음 한 흐름을 끝까지 만든다.

**작품 생성 → 안정 ID로 일부 조회 → 사람 수정 → AI 부분 변경 제안 → revision 검사 → 적용 또는 전체 거절 → 웹 재생 → 저장 → .sjg 내보내기 → 가져오기 → 복원 확인.**

필수 사항:

- 스키마와 모듈별 의미 검증. 구조 검증 성공과 실행 지원을 구분한다.
- 변경은 대상 ID와 base revision에 결합한다. 오래된 revision·없는 대상·잘못된 변경이 하나라도 있으면 묶음 전체를 무변경으로 거절한다.
- 사람이 먼저 수정한 내용은 AI의 오래된 제안으로 덮어쓰지 않는다. 무관한 블록·필드·알 수 없는 모듈 데이터도 보존한다.
- 성공한 변경은 새 revision과 변경 근거를 남기고 되돌릴 수 있다. 충돌 후 자동 재시도로 사용자 선택을 대신하지 않는다.
- 정적 페이지, 스크롤 장면, 선택형 장면을 실제 재생한다. 현재 예제는 입력 후보일 뿐 재생 증거가 아니다.
- 최소 두 종류의 모듈과 미지원 모듈의 명시적 비활성 대체 표현을 확인한다. 미지원 데이터를 삭제하지 않는다.
- 파일을 가져왔다는 이유로 코드를 실행하거나 URL·플러그인을 자동으로 불러오지 않는다. 실행과 자원 사용은 호스트 권한 경계에서 통제한다.
- 프레임워크·네트워크 없이 가능한 core 검증과 실제 호스트·서비스 검증을 구분한다.

처음부터 거대한 편집 UI, 모든 AI SDK, 영상 시스템, 새로운 DB/서버/DSL을 만들지 않는다. 검증된 재사용 경계가 있을 때 필요한 어댑터만 추가한다.

## 4. 손잡고 연결의 실제 검증

기존 도구와 인증·발행 체계를 우선 사용한다. `.sjg` 수신·변환이 없으면 기존 경로의 최소 확장을 검토한다. 다른 저장소 수정이나 운영 변경은 현재 승인 범위부터 확인한다.

명시적으로 허용된 계정과 작품으로 **비공개 저장 → 같은 revision 재조회 → 비공개 미리보기**를 확인한다. 소유자·다른 계정·익명 접근, 오래된 수정, 지원/변환/미지원 결과를 검증한다. 실제 서비스 범위를 얻지 못하면 이 항목을 미검증으로 남기고 다른 core 작업을 계속한다.

공개 발행은 별도 사용자 승인 뒤에만 실행한다. 승인 대상은 실제로 검토한 작품·revision·발행 위치다. 클라이언트 데이터의 승인 표시로 서버 권한 검사를 대신하지 않는다. 개인 작품이나 실제 계정 정보는 공개 테스트 자산에 넣지 않는다.

## 5. 완료 판단표

| 항목 | 필요한 증거 |
| --- | --- |
| 공통 모델 | 세 종류 작품의 실제 재생 결과와 구조·의미 비교 |
| 파일 이식성 | 내보내기/가져오기 후 ID·내용·의도한 표현·모듈 데이터 동일성, 자산 포함/참조 정책 |
| 부분 수정 | AI가 지정 블록만 바꾸고 사람의 수정과 무관한 데이터가 유지되는 테스트 |
| 충돌·복원 | 오래된 revision·잘못된 묶음의 전체 무변경, 성공 변경 undo, history/revision 결과 |
| 모듈 확장 | 두 번째 모듈 추가, 미지원 모듈 보존·비활성 대체 표현, 잘못된 payload 거절 |
| 가져오기 경계 | 손상·과대 입력·미지원 버전·잘못된 자산 경로·외부 실행 요청의 처리 |
| 비공개 연결 | 실제 서비스의 소유자/다른 계정/익명 결과와 저장·미리보기 revision 일치 |
| 발행 분리 | 저장·미리보기로 공개되지 않음; 승인 검사는 허용된 환경에서 확인 |
| 호스트 이식성 | core가 호스트별 데이터 변형 없이 쓰이는 증거; 미확인 호스트는 별도 표시 |
| 공개 코드 경계 | 의존성/재사용 출처·라이선스·게시 파일 검토, 개인 데이터 없음 |

단순 문서·목업·스키마 통과만으로 이 기초공사 전체를 완료했다고 하지 않는다. 전체 검증을 막는 외부 조건이 있으면 구현된 범위·실측된 범위·남은 조건을 나누어 보고한다.

## 6. 결과 회수

보고에는 조사한 자산과 버전, 재사용한 부분, 결정과 대안, 코드·테스트·빌드 명령 및 환경, 실패·미검증·제약, 다음 최소 작업을 담는다. 저장소 URL과 정확한 커밋을 남긴다. 테스트 통과를 실제 서비스·계정·기기 수용으로 확대하지 않는다.

승인된 실행은 기존 Project/Task/Work와 연결해 지속 결과를 기록한다. 기존 Task의 완료 조건을 충족하지 않았다면 상태를 완료로 바꾸지 않는다. 신규 저장소 bootstrap 결과와 전체 Foundation Engineering 완료를 구분한다.
